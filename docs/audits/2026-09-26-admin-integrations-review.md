## Fixed defects and direct verification

1. **Large import diagnostics lost later rows.** A single `select` returned only the API's capped first page. The diagnostic download now follows ordered row-number cursors until an empty page, including when a deployment configures a cap below the requested page size. A later page failure rejects the entire read rather than exporting an apparently complete partial receipt.
2. **Support attachment failures invited duplicate tickets.** Ticket+initial message had already committed when upload/linking failed, but the hook threw and the form remained open. The hook now returns the saved ticket plus an attachment warning, refreshes the ticket queue, and Help Center navigates to that ticket with instructions to attach the file in a reply. Orphan cleanup and cleanup-error reporting are retained.
3. **Release-control failures looked like disabled features.** Missing kill-switch data enabled the wrong action, while a failed feature evaluation read “Off for you.” Loading/error states now disable the dependent action and display unavailable explicitly; retry includes the kill-switch query.
4. **Completed webhook acknowledgements could time out or be rejected.** The pinned HTTPS reader always awaited EOF and interpreted the first status line as final. It now completes length-delimited and no-content responses without requiring peer closure, advances past informational 100/103 responses, measures Content-Length in bytes, rejects malformed framing, and rejects prematurely truncated bodies. Response and header memory caps remain bounded. Existing transfer-encoded responses retain the connection-close behavior.
5. **Policy completion and assignment recovery were misleading.** A campaign with no recipients read “Lifecycle current,” even beside a completed earlier campaign. It now requests assignments. Manual assignment now recognizes the actual PostgREST duplicate-error object, retains failed recipients for retry, prevents dismissal while assigning and disables submission when session assurance expires.
6. **An earlier policy review could affect a later one.** Closing policy A and opening B before A's signed-URL request completed could display A's document under B's signing action. A request token now binds document loading, errors, knowledge-check completion and attestation completion to the same review. Knowledge-check components reset by attestation ID, and signing remains disabled until that review's document and required knowledge check are ready. Employee-profile lookup errors now offer retry; an unlinked account is distinguished from no outstanding assignments.
7. **Auditor access restrictions appeared to remove knowledge checks.** The author-side question table excludes auditors because it contains the answer key. Its empty RLS result was displayed as “no knowledge check.” The panel now explains the author-only access and does not issue that restricted query for readers.
8. **Large policy libraries lost required review metadata.** Document/campaign/version reads stopped at one API response, so a valid assigned version beyond the row cap appeared unavailable. These reads now page in stable order until empty, advance by the returned row count, preserve every scope filter, and reject later-page failures. The existing assignment reader also now handles a configured cap below 1,000. Personal review surfaces metadata failures with retry instead of presenting an unusable review action.

## Policy workflow evidence

- **Routes and roles:** `/app/policy-documents` and its `/:id` route use `POLICY_ROLES`; author controls use `canWritePolicyDocuments` for platform administrators, organization administrators and facility managers. `/me/attestations` and `/app/my-attestations` share personal-review behavior, while `/attestations` resolves the recipient's current role. Auditors retain read access without authoring controls or answer keys.
- **Create, upload and publish:** The list is paginated/searchable with retry, and complete metadata reads now span the API row cap. Required titles are trimmed. Uploads hash the exact file bytes and use a unique tenant/document storage path; row-creation failure attempts orphan cleanup. All authoring mutations recheck current policy-write assurance. `publish_policy_document_version` checks role, tenant, parent and assurance, then publishes and advances the document pointer atomically. Published content is immutable; publication closes older campaigns and supersedes their pending assignments while retaining signed evidence.
- **Campaigns and assignments:** `create_policy_campaign_with_questions` creates the campaign, validated questions, declarative population and recurrence anchor in one transaction. Manual assignment is independently recoverable per employee; the insert trigger derives tenant, facility, version and due date and refuses forged completed evidence or closed campaigns. Targeting author scope, active recipient eligibility, daily materialization, recurrence population, skipped-empty-cycle evidence and reminder-recipient stamping have dedicated database tests. The lifecycle summarizes the current version, preserves overdue/pending precedence, and no longer treats an unpopulated campaign as completed.
- **Review, knowledge checks and signing:** Employee assignment reads wait for the linked employee ID. Private storage supplies temporary review URLs. The learner question RPC omits answer keys; grading and attempt caps remain server-side with append-only attempts. `attest-policy` verifies the authenticated user owns the assigned employee, rejects missing document fingerprints and superseded/already-signed rows, checks passing attempts with the service-role client, and writes attributed evidence only while the row is still pending and unsuperseded. Signing refreshes assignments and notifications. The new page regressions exercise overlapping document requests, stale failures, stale knowledge-check results and late signing completion.

## PR review follow-up: webhook response cap

The automated review identified an incomplete-body case at the pinned transport's 96 KiB wire buffer limit. The existing guard skipped `Content-Length` verification when the buffer filled, so a truncated 2xx body could be accepted. Two new regressions reproduced the failure before the fix: a declared 1,000,000-byte body stopped at the cap, and a response exactly one body byte short at the cap. Removing the cap exemption rejects both. A third regression verifies that a complete response exactly at the wire cap still succeeds without an extra socket read, with the returned diagnostic body limited to 64 KiB. Connection cleanup remains verified.

`deno test --allow-env supabase/functions/_shared/phase2Integration.test.ts supabase/functions/push-subscriptions/handler.test.ts`: **33 passed** (17 transport/integration and 16 push-handler tests). This follow-up changes the declared-length completeness check; transfer-encoded and connection-close framing behavior is otherwise unchanged.
